# Viva.Beta.V1 — пакет изменений (частичная реализация)

## Добавлено
- Viva Shop: баланс внутриигровых звёзд, пакеты 50/100/250/500 через Telegram Stars и зачисление только после `successful_payment`. Повторные charge-id не начисляют валюту второй раз.
- Набор новичка: стоимость, деньги, опыт, экипировка, доступность регулируются администрацией.
- Viva Pass и ViVip: по 30 уровней и две ветки наград; ViVip стоит 250 звёзд. Доступность наград привязана к реальному уровню игрока.
- Реферальные Telegram-ссылки `/start ref_ID`, единоразовые награды пригласившему и новому игроку с изменяемыми суммами.
- Партнёрские заявки: проверяется, что бот — администратор указанной группы или канала; одобрение в админке.
- Партнёрские промокоды: максимум 100 использований, срок 30 минут, интервал 3 часа, до трёх кейсов. Награды резервируются из собственности автора заранее.
- Отдельная настройка техработ для вкладок и панель админа V14.
- Снимок SQLite через `/backup` в Telegram и из панели V14. Загрузка SQLite файлом боту для проверки и подготовки к восстановлению. **Не заменяет рабочую БД на ходу**.
- Аквариум: доход каждой рыбы 3% её стоимости в час, с сохранением прежнего ограничения времени накопления.
- Кейсы: проверка 5 мест по соответствующему типу экипировки перед открытием, отключена автоматическая продажа из-за переполнения.
- Топ-10 вместо топ-50.

## Ещё не завершено
- Полный редизайн кейсов и анимации, карточки получения предметов с выбором «забрать/продать/крутить», рекорды локаций, анимация рыб в аквариуме, интерфейс наград, сортировки инвентаря, улучшения чата и модераторов.
- Самостоятельная загрузка и восстановление БД **в один клик** без остановки сервера: для SQLite опасно, файл подготовлен для безопасного восстановления при остановленном приложении.
- Расширенная выдача кейсов через обычные промокоды администратора: партнёрские промокоды уже поддерживают кейсы.

## Перед запуском
1. Установить зависимости из `requirements.txt`.
2. Настроить `BOT_TOKEN`, `WEBAPP_URL`, `DB_PATH`. **Не выкладывать секреты в git**.
3. Запустить `uvicorn main:app --host 0.0.0.0 --port 8000 --workers 1`.
4. Сначала проверить на тестовом боте и тестовой базе, особенно оплату XTR и возвраты.
5. Для SQLite использовать постоянный диск, например `/var/data/database.db`, иначе Render может стереть локальную базу при перезапуске.
6. В админке V14 есть новые настройки, а в Telegram команда `/backup` отправляет файл базы только ID администратора.

**Важно:** автоматические тесты сервера не запускались: в сборочной среде отсутствует aiogram и недоступна установка пакетов из сети. Проверены только синтаксис Python и JavaScript. Не считайте сборку проверенной для работы с реальными платежами до интеграционного теста.

## Дополнительная сборка visual_update
- Добавлена новая визуальная тема поверх существующих компонентов (`v15.css`, `v15.js`), сервер выдаёт эти файлы через белый список.
- Рюкзак: компактные карточки рыбы с открытием отдельной панели действий, сортировка по редкости и весу; снасти также сортируются.
- Рыбу можно отпускать в обмен на небольшое количество EXP через атомарный серверный эндпоинт `/api/v11/fish/release`. Доступность рынка пока помечена замком.
- Аквариум: анимированные силуэты рыб, целочисленная индикация дохода, зелёная кнопка получения. Само начисление остаётся серверным.
- Кейсы: категории отдельно, компактные карточки, скрытый по умолчанию перечень шансов, предупреждение о местах, карточки наград и кнопка нового открытия после результата. Сервер запрещает открытие при полном рюкзаке.
- Рыбалка: компактные кнопки локаций и сортировка списка шансов. Шкала уровня и баланс стали выразительнее; нажатие на баланс меняет краткую и полную запись.
- Личный маркер в топ-10, если игрок присутствует в рейтинге; анимации учитывают режим пониженного движения.

### Пока не сделано / не проверено
- Реальные серверные рекорды по каждой локации, полноценная система подарочных карточек и новый редактор наград, отдельная блокировка только чата, абсолютная проверка всех действий админки, кастомизация модерации.
- Анимация вываживания и многократного открытия сохранена существующая; художественный редизайн этих анимаций не является полностью завершённым.
- Пользовательский выбор «оставить все или продать все» непосредственно на странице результата кейса не реализован. Предметы зачисляются сервером при открытии, их можно продавать из рюкзака.
- Интеграционные тесты в живом Telegram и тестовые платежи не проводились.
